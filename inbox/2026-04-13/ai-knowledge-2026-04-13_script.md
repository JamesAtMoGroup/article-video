# 逐字稿 — 什麼是 MCP？為什麼最近大家都在講

嗨，歡迎來到每日 AI 知識庫。今天我們來聊一個最近在 AI 圈超級熱門的詞，MCP。。

你可能在一些社群、Podcast 或是 AI 工具的介紹裡面聽過它，但一直搞不清楚它到底是什麼。今天我來幫你把它說清楚。。

MCP 的全名叫做 Model Context Protocol，翻成中文大概是模型情境協議。光聽名字可能有點硬，所以我們先跳過名字，直接講它是幹嘛的。。

你有沒有想過為什麼 AI 很聰明，卻沒有辦法幫你把今天的會議記錄存進 Google Drive，或是幫你查一下明天的行事曆？。

因為 AI 模型本身是孤立的，它就像一顆很厲害的大腦，但沒有手，沒有眼睛，沒有辦法主動碰到外面的世界。。

MCP 就是幫 AI 長出這些手腳的標準。。

具體來說，MCP 定義了一套規則，讓 AI 模型可以和各種外部工具說同一種語言。。

開發者只要按照這套規則做好一個 MCP 伺服器，AI 就能連上它，使用它的功能。。

不管是讀本地資料夾，搜尋 Notion，操作瀏覽器，還是查資料庫，都可以。。

拿一個更生活化的比喻來說，以前每台裝置都用自己的接頭，連個滑鼠都要找對應的插槽，很麻煩。。

MCP 就像是 USB 的出現，統一了規格，讓所有東西都能插在一起。。

簡單來說，一個標準解決一堆問題。。

好，這裡有一個問題給你想一想。。

你現在使用的 AI 工具，有沒有哪些事情它懂但做不到？。

那可能就是它還沒連上對的 MCP。。

MCP 是由 Anthropic，也就是 Claude 背後的公司在 2024 年底提出的開放標準。。

一開始只有 Claude 自己在使用。。

但沒多久，OpenAI、Google、微軟等大廠都開始跟進支援。。

整個 AI 開發社群的討論熱度直線上升。。

為什麼這麼受關注？原因有三個。。

第一，它是開放的。。

MCP 不是某家公司的私有規格。。

任何人都可以按照標準做自己的 MCP 伺服器。。

不需要授權，不需要付費。。

這讓生態系長得非常快。。

短時間內就冒出了幾百個現成的 MCP 工具。。

第二，它解決了一個真實的痛點。。

以前每個 AI 平台都想接外部工具。。

都要自己寫一套整合，費時費力又容易出錯。。

MCP 統一了這件事。。

開發者做一次，就能被多個 AI 使用。。

第三，也是最重要的。。

它讓 AI Agent 真正可用。。

所謂的 AI Agent 就是能自主完成多步驟任務的 AI。。

Agent 要跑起來，就需要穩定地連接各種工具。。

MCP 補上了這塊基礎建設，等於給 Agent 的崛起鋪好了路。。

這裡留一個問題給你。。

如果你是一個開發者，有了 MCP 這套標準，。

你會最想讓 AI 連接哪些工具？。

你可能不會自己去架設 MCP，但這件事對你的影響其實比你想的大。。

現在已經有越來越多工具支援 MCP，。

包括 Claude Desktop、Cursor 這款 AI 程式編輯器，一些 AI 筆記工具。。

如果你在用這些工具，你已經可以透過 MCP 讓 AI 幫你做這些事。。

直接讀取本機資料夾的檔案，搜尋你的 Notion 或 Google Drive。。

查詢今天的行事曆，甚至幫你建立活動，發送 Slack 訊息或 Gmail。。

這些能力幾個月前還要靠複雜設定才能做到，現在只要開啟對應的 MCP 就行。。

不過這裡有一個重要的提醒，我想特別提。。

說一下。。

MCP 連接外部服務，也代表 AI 有機會讀取你的私人資料。。

你在授權任何 MCP 連接之前，應該要先想清楚。。

這個工具可信嗎？。

它會把我的資料傳到哪裡？。

這不是要你不要用它，而是要你有意識地使用它。。

而不是什麼都接、什麼都開。。

選擇 MCP 工具時，可以優先看是否開源，。

有沒有明確的隱私政策，背後是哪家公司在維護。。

今天留給你思考的最後一個問題是，。

如果有一個 MCP 可以讓 AI 讀取你所有的 Gmail，你願意開啟嗎？。

你的判斷標準又是什麼？。

最後來快速整理今天的內容。。

第一，MCP 是一套讓 AI 連接外部工具的開放標準，就像 USB 一樣統一規格。。

第二，它之所以受關注，是因為它開放、解決真實痛點，。

而且讓 AI Agent 真正有辦法落地。。

第三，作為使用者，MCP 擴大了 AI 的能力，。

但連接外部服務前一定要先評估隱私風險。。
